### Minimum schema rationale (before migration)

Existing `tool_operations.output` and turn JSON cannot register a regular-file
identity, distinguish producer loss from preview loss, reserve concurrent capture
bytes, or retain expiry/interruption facts independently of immutable outcomes.
An additive `tool_output_resources` table in the existing SQLite connection is
therefore necessary. It references the original operation/session and stores only
bounded descriptors: generated name, dev/inode, original Location/config generation
and source, admitted/published bytes/lines, capture state, completion/expiry facts.
No log rewriting, second connection/store/root lock, full-payload SQLite column,
new dependency or separate quota pool. Writer/reader leases remain process-local
to that Db owner; durable active rows recover interrupted without producers.
