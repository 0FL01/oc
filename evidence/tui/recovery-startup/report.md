## Independent-review follow-up — switch safety and saved selection (same uncommitted HEAD)

The preceding sections describe the initial startup slice. A review found two additional failures: `/location` passed raw `CoreError::Application` text to the toast, and malformed persisted `tui.selection.legacy_epoch` returned before the worker's readiness acknowledgement, causing a false `Runtime` category. Both are now covered by isolated product PTY tests. The initial generic non-fatal warning also now has safe source-specific guidance.

- `oc-core::session::LocationSwitchFailure` is a typed category carried alongside the unchanged detailed API error in `CoreError::LocationSwitch`. Application composition, saved-selection and runtime switch failures are classified at the point of failure, without string matching. The TUI matches only the category; unknown/rejected core errors receive a static fallback. Post-switch history and selection query errors also have static messages. The old TUI workspace is not reset on a refused switch, and page/catalog are obtained before updating the view after an accepted switch. The application's target generation is not published on a refused switch. `LocationSnapshot::diagnostics` remains available to existing non-TUI callers; the TUI never renders it.
- Startup readiness now returns a typed `SpawnIssue` on every known pre-ready failure, including a malformed saved legacy-selection epoch (`Storage`, not `Runtime`); the headless API still receives the underlying detailed error. Successful composition attaches allowlisted `StartupNotice` sources (definitions, plugin marker, DCP settings, instruction sources), with a saved-selection notice when worker warnings occur. A successful Location switch supplies the same source categories. Messages are static and contain no user-supplied filenames, model IDs, paths, config keys or provider values; static hints may name the documented `opencode.json/jsonc` config format. The normal Location footer and user-entered `/location` draft remain ordinary UI data.
- Isolated debug and rebuilt release PTYs: corrupt SQLite epoch shows **Storage or saved selection failed**, exit **1**, restored terminal; isolated `oc run` fails **1** with its existing detailed `malformed scoped selection preference` text and no network request. In three separate processes, `/location` to an unknown model, malformed config and corrupt target selection displays only **Location configuration failed** or **Location storage failed**, never the planted `LEAKME-*` model/key values or raw config filename. The refused draft and active application survive: after clearing the draft, `/location` to a valid target succeeds in the **same** child; the target's non-fatal DCP warning is shown as a safe source category, no planted warning key appears, and Ctrl+C exits **0** with terminal state restored. An application API regression also asserts `LocationSwitchFailure::Configuration`, retains the detailed API error and verifies the original catalog after refusal. These PTYs do not send a provider turn.
