## Owner policy and evidence

- The adapters send `ClientRequest::CallToolRequest` via rmcp `send_cancellable_request` and retain the `RequestHandle`; Esc/deadline invokes bounded `RequestHandle::cancel` with the exact request ID. Send/response share one deadline. No parsing of arbitrary error text. A request with no proven result is persisted as **`unknown`**, stops the batch and fails the turn with `MCP outcome unknown; retry may duplicate side effects`; the model does not get an automatic next-round replay.
- A poisoned generation is explicitly closed before a subsequent owner action. The stdio process group is killed/reaped, including a server that ignored the cancellation notification. Its explicit PTY retry spawns a fresh child only after the first is dead; durable turn statuses are `failed`, `completed`, and the original tool operation stays `unknown`. The old and new calls never overlap in the fake. Drop of an in-flight runtime call also poisons the generation via RAII.
- The remote fixture checks the cancellation notification's `requestId` matches the original `tools/call` ID, POST and protocol version; it also observes client-side TCP closure while still holding the first server-side operation. HTTP teardown and a 202 for notification do **not** prove that a remote effect stopped. This application owner therefore refuses explicit retry with safe `unsafe_retry` code, no second provider request/call; its tool operation remains `unknown`. A separate application restart/independent remote service is outside this in-process guarantee; reconciliation with that service is required before assuming a repeat is safe.
- If cancellation notification or generation closure fails, cleanup is surfaced as `mcp shutdown failed`, the owner is marked poisoned and cannot silently attach/recycle a new client. A third PTY fixture returns HTTP 500 with `PRIVATE_CANCEL_FAILURE` for the notification: operation remains `unknown`, the TUI shows the safe cleanup code without the response body, retry sends no second call, and the actual binary exits nonzero on shutdown. Remote retry quarantine persists for this runtime, including after config reload.
