## Implemented / observed

- One active panel owns keys, paste, pointer hits and the visible Search cursor. Closing it returns to the existing prompt draft and end-of-draft caret. The model choice is applied **before** replacing Model with Variant, as in pinned upstream; Esc from Variant closes to the prompt, does not reopen Model or roll back the selected model. No nested historical stack is implied by this replacement flow. Clearing modal search, disabled action handling, active submit/cancel and the pre-existing informational-panel Ctrl+C shutdown binding remain intact.
- Enabled Crossterm mouse capture upon entering the alternate screen and disabled it on normal, error and panic restoration. `UiEvent::Mouse` routes wheel events to the transcript only without a modal. With a modal, all mouse events are consumed there: backdrop/`esc` dismiss on matching left-button press/release, Search retains modal input ownership, option hover changes only the focus row, option click submits exactly one existing application intent, wheel scrolls the option viewport without changing the effective model or selection, drag-release across the backdrop does not dismiss. Hit rows and painted rows share geometry (including category headers, filtered lists and scroll offset). Keyboard navigation restores selected-row visibility after wheel scrolling.
- Two actual 80×24 PTY tests inject raw SGR mouse sequences: click outside Model and Commands, click Search and the filtered model option, Esc from the resulting Variant, reopen Variant and click `fast`; actual provider request uses `alt-model`, `reasoning.effort=high`, and the original draft exactly once, with saved selection. The raw terminal cursor moves from prompt to Search and back. Another PTY scrolls 12 rows by wheel, hovers the offscreen model brought into view, submits it, and observes `mouse-12` on the actual provider wire. Unit test verifies option hit mapping, independent scroll versus selection, hover, drag release, single-click intent and restoration of editor input. PTY verifies `?1006h` / `?1006l` and terminal cooked-mode recovery.

## Limits

Mouse reporting is conditional on terminal support. Actual raw PTY coverage validates xterm SGR 1006; legacy X10/URXVT encodings, non-PTY terminals, drag-to-copy/selection-release semantics and touchpads without reporting were not qualified. Mouse capture is enabled through the existing stderr terminal control path (the same path as alternate-screen entry); a launch with redirected stderr and interactive stdout has not been qualified. The current editor retains only its end-of-draft caret; arbitrary in-draft caret movement belongs to V05. Full-frame visual parity, full upstream dialog capabilities and other V04 panels are not claimed by this mouse/focus slice.
