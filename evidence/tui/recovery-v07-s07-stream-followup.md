This supplements [the archive/resource test](recovery-v07-s07-report.md) and [the worker-queue sample](recovery-v07-s07-queue-followup.md); it does not replace their historical results. `s07_pty_equal_view_archive_resource_samples` now submits one actual streamed Responses turn in each independently launched `oc tui` PTY (120×40, identical 200-message active tail, with zero or 3,000 older stored messages). The 3,000-message fixture marks the last older message as a verified prune boundary, **without deleting the archive**; both fixture configurations disable DCP anchors carrying different message IDs. The test compares the **complete provider request JSON**, not normalized or filtered inputs, across both runs, and checks all old message IDs, roles and text after the turn. Both runs retain the same previous scroll, resize, paste, tool-card, Commands, viewport, terminal-restore and child-reaping checks.

The fake provider flushes three actual SSE text deltas, opening a Rust Markdown fence. It holds completion until the intermediate fragment appears in the real PTY while `esc interrupt` still indicates an active turn; it then flushes three more deltas, closes the fence, sends a successful terminal event, and the test checks the final visible content, idle state, one request and durable user/assistant messages. This is progressive streaming, not a heartbeat followed by one complete delta. The selected model budget is raised only in these two isolated fixture configs so the common 200-message context can be submitted; the real application still enforces its configured model limit.

`OC_TUI_TEST_METRICS` additionally samples current and maximum observed live text/reasoning bytes, frozen live-part count and persistent Markdown-cache payload/index bytes across active and parked views at existing frame boundaries. The source-page cache keeps its index-byte count on replacement and eviction; sampling does not reparse Markdown. The values are **sampled**, not continuous peaks or allocator high-water marks. The cache counter excludes `Vec`/`String` spare capacity, object overhead, transient page copies, and rendering allocations. Worker-receiver occupancy is sampled around drains and overwritten-message counts are not elapsed-time lag or input-queue occupancy.
