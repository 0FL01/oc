## Test and observed effects

The same fixture sentinel contains `ESC[2J` (CSI erase), `ESC]52;c;WA== BEL` (OSC52), `ESC]8;;https://example.invalid/x ESC\` (OSC8), BEL, and CR. Model text also contains `Unicode: café 漢字\nNext line intact`. The successful MCP result carries the sentinel; an `isError:true` MCP result carries it in the server response. The test decodes the **captured VT stream into cells** (including wide Unicode, cursor movement and redraws), visits the successful tool's `/cards` result view, waits for the reasoning title, the error card, and the completed `· Nms` footer, then exits, restarts the same session and revisits transcript and card detail. It checks exactly two stdio tool calls, two main Responses requests plus optional ancillary title request, one completed turn, persisted exact original model text and original JSON tool input, as well as no provider/tool call on replay. The actual successful MCP output is checked in SQLite and the next Responses input. Alternate-screen enter/leave bytes are present on both exits.

Raw VT measured in the final focused `--nocapture` run, **before leaving the alternate screen**: initial ready capture 4,168 bytes → 15,664 bytes through live tool-result detail; 377 CSI prefixes including trusted cursor/style instructions. On the restarted session: 13,277 bytes through replay detail; 298 CSI prefixes. `ESC[2J` count 0 before and after live injection, 0 on replay; OSC52 0, OSC8 0, BEL 0, and all raw CR 0 on both. The raw sentinel byte string is absent. Legitimate renderer CSI cursor/style bytes and trusted alternate-screen setup/cleanup are intentionally distinguished from payload patterns; no blanket ban on terminal control bytes is asserted. The decoded grid contains `Unicode: café 漢字`, `Next line intact`, a safely displayed collapsed reasoning title, a tool argument with replacement glyphs instead of control bytes, a `probe__fail` error card, and the successful result detail `tool output: CSI[2J ...` without control instructions. The final live/restarted transcript and successful card detail remain accessible after restart.

The existing paths explain this result: `messages.rs::safe_text` and `sanitize_line` remove controls at transcript presentation (including Markdown, reasoning/title, footer and recorded tool cards); `views.rs::escaped_result` bounds/escapes card-detail rows. Independently, **pre-existing** `mcp_result.rs::redact` removes control characters (except newline/tab) from successful MCP results before storage/provider continuation, and the `isError` result becomes the typed `error: mcp tool reported failure` rather than arbitrary server prose. The test asserts those *actual* policies; it does not substitute a fake tool result for capture. The assistant's durable SQLite text retains the exact original sentinel and newlines; raw tool input is JSON-escaped in SQLite but decodes to the exact original sentinel. The successful tool's persisted text is the MCP adapter's existing projected text, including ordinary characters, not the original raw server control bytes.
