## Slice 2 — IDs beyond 9999 (no product change)

- `dcp.rs::tests::dcp320_ids_beyond_9999_keep_block_order_nesting_and_restart`:
  messages `m9998…m10004` and blocks `b9999`/`b10000` from the global high
  water project in sequence order and identically after reopen; raw overlap is
  refused (`ExistingOverlap`); nested `plan_active_compression` from `b9999`
  through `m10003` creates `b10001`, consumes both blocks and expands both
  summaries; position-based range planning resolves `m10000…m10003`.
- Textual `ORDER BY id` (`b10000` < `b9999`) is not an ownership risk: the
  runtime projects only active roots (`compaction_graph`) and the candidate
  graph clears consumed members before `project_active_rows`. A synthetic graph
  that kept consumed members reproduced stale raw rows, so the test pins the
  production invariant instead.

## Slice 3 — compaction nudge replay (no product change)

- `runtime_compaction_tests.rs::compaction_auto_threshold_and_known_overflow_keep_tool_effect_once`
  now asserts that the native auto-compaction summary request carries no DCP
  reminder, context anchors or stable-ID index, that the following main request
  keeps its own anchors, and that the persisted `dcp.nudge.*` cadence
  (`iteration`, `turns_since_compress`, `emitted`) equals the same turn without
  compaction. Native has no shared summary prefix to replay, so the donor's
  `createAnchors=false` path has nothing to adopt; cadence cannot double-advance
  and no nudge attaches to later content.
