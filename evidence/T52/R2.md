# T52 R2 — TuiState slices

## Result

R1 implementation `eb6e7e109` → four production parts plus the existing state
owner. `TuiState` fields, constructors/reset, counters and shared deadlines stay
in `app.rs`; input/panels/pointer dispatch, transcript/selection/paging, tab
clocks and live receipts/events have one implementation each. Public facade
paths are explicit re-exports; ScriptDriver/PumpOutcome remain non-test API.

Private method seams are owner-scoped only when another part calls them.
TabView exposes only the two pointer-dispatch fields and reset_hover to its
owner. Tab tests are declared under tabs, preserving private pulse/marquee
types and fields rather than exposing them for tests. Shared test fixtures have
cfg(test)-only owner visibility. The final identity inventory maps the tab
prefix `app::tests::<name>` → `app::tabs::tests::<name>` one-to-one.

## Risks

The render diagnostic is an in-memory structural regression, **not** an
actual-executable parity or a new VIS38/V09 qualification. Existing actual-PTY
cases were run independently. The external fixture compiler emitted the same
deprecation warning for reading TestBackend Cell::skip on both sides; this
field was deliberately included in the complete comparison. No production
warning remains. Initial compile diagnosed child-private cross-calls; fixing
their scopes/declarations did not change algorithms or resource ownership.
