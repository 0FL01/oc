# T33 — Durable tool execution и recovery

Audit commit: `fc796830cf336655bebf63b591fe0fd36cdd4310`. Findings: F06, F16. Эти требования уточняют существующие A01–A13, не расширяют продуктовый scope.

## Что исправить

Для каждого tool call выполнить: validate → permission decision → durable intent commit → side effect → durable outcome. На ошибке intent/DB нельзя начинать operation. Не игнорировать storage errors у MCP. Сохранить исходный порядок смешанного builtin/MCP batch; не исполнять все builtins раньше остальных просто для удобства dispatch.

После crash помечать незавершённые operations unknown при открытии application, не автоматически повторять shell/patch/MCP. Intent должен включать session/turn/call IDs и достаточно метаданных для сопоставления. Accepted input, state transition и durable event фиксируются согласованно; logical commit assistant/turn result не должен давать completed history при незавершённом turn. Не строить distributed exactly-once.

Исправить blob recovery: наличие blob-файла не доказывает наличие/валидность metadata row. Вернуть digest можно только когда content валиден и доступен через read API. Orphan repair, quota accounting, safe temp cleanup, directory sync и crash ordering покрыть fault injection. Не считать старые blob helpers доказательством того, что все outputs реально вынесены в них.

## Критерии приёмки

### AUD06 — Intent precedes mutation and survives process kill

Inject storage failure до intent исключает изменение файла/вызов MCP. Kill subprocess после side effect до outcome даёт durable started→unknown после reopen, без повторного исполнения.

### AUD07 — Mixed tool order and terminal transaction

Builtin/MCP/builtin исполняются в объявленном порядке. DB fault не скрывается. Accepted input и terminal message/event/turn не расходятся при restart.

### AUD08 — Existing orphan blob is repaired or rejected

Создать valid content-addressed файл без DB row, затем write_blob тех же bytes. Успешно возвращённый digest читается через read_blob; crash после rename и до row не создаёт ложного успеха; quota и GC не удаляют referenced blob.
