# T31 — Подключить реальный application path

Audit commit: `fc796830cf336655bebf63b591fe0fd36cdd4310`. Findings: F01. Эти требования уточняют существующие A01–A13, не расширяют продуктовый scope.

## Что исправить

Создать одну composition factory для CLI и TUI: source discovery → validated immutable generation → provider/model catalog → Runtime/application handle → UI. MockProvider остаётся только явным тестовым/демо-профилем, никогда автоматическим fallback. Первое действие — добавить падающий binary E2E, который слушает loopback fake endpoint и ожидает реальный запрос; не делать новый live вызов ради проверки wiring.

Не поддерживать два независимых владельца сессии: mock CoreApp и «настоящий» Runtime должны быть сведены к одному application interface. Ядро определяет команды/события/ошибки, composition root собирает adapters. Можно сначала ввести узкий bridge, не переписывая все crates. Но история и permission transitions должны иметь одного владельца.

Убрать временный default storage `oc-t05-*` из обычного запуска: использовать отдельный устойчивый XDG data namespace для oc, с явным --data-dir для тестов. Не открывать upstream DB на запись. UI не должен сам сохранять rejected input или фиктивно подтверждать DB errors. Duplicate-session обрабатывать по точному constraint, а не по любому SQLite error.

До T32/T33 никаких ручных испытаний изменений на ценном пользовательском репозитории: только temp fixture. После T34 тот же binary smoke обязан пройти по исправленному structured Responses пути.

## Критерии приёмки

### AUD01 — Executable sends a real configured request

Запустить target/debug/oc run как subprocess с временными HOME/XDG/project/data и local fake Responses. Endpoint получил запрос; выбранный model и env credentials использованы; ответ не echo. При отсутствии конфигурации nonzero diagnostic, не mock fallback.

### AUD02 — Same application for CLI/TUI and durable restart

Отдельные процессы CLI и PTY TUI используют один config/runtime contract. После закрытия и нового запуска с тем же data-root история восстанавливается и реально участвует в следующем запросе. Own storage не находится в tmp по умолчанию.
