# T40 — Ограничить активный контекст, а не подменять его обрезкой

Audit commit: `fc796830cf336655bebf63b591fe0fd36cdd4310`. Findings: F15. Эти требования уточняют существующие A01–A13, не расширяют продуктовый scope.

## Что исправить

Убрать read_history_full из hot-path materialization неограниченного архива. История и output blobs живут на диске; application собирает только активную projection по ссылкам/страницам с проверенными byte/token budgets. Не строить весь giant String лишь затем, чтобы обрезать его до 64 KiB.

Не использовать произвольный 64-KiB cap как замену настроенному 500k context и DCP. Safety byte cap и model token admission — разные ограничения. Переполнение даёт явную политику compress/admission/error; не удалять пользовательские instructions/history без диагностики. User/prior-only payload также подчиняется bound. Token estimate — эвристика, не известный точный счётчик любого proxy model; reserves и ошибки описаны честно.

Output preview не становится единственной копией результата и не должен незаметно заменить доступные модели данные на первые 2048 bytes. Полный допустимый result хранится с quota/blob reference и явным truncation/cursor для дальнейшего read. SSE/events/queues bounded по bytes; shutdown не теряет единственный durable результат.

Перезапустить измерения на реальном бинарнике при одинаковом активном контексте и существенно разном архиве. Зафиксировать workload, toolchain, host, allocator, baseline/peak/post-idle RSS/PSS/дерево процессов, очереди/children. Не выдавать отсутствие крутизны роста SQLite на двух коротких эпохах за отсутствие memory leak. Численный SLO не менять после наблюдения результата, чтобы скрыть регрессию.

## Критерии приёмки

### AUD32 — Equal active context, growing archive

Synthetic binary workload с малым и большим архивом при одинаковой активной projection показывает bounded retained state/peak construction, без полного чтения history. Размеры workload фиксируются до прогона; отчёт содержит фактические значения.

### AUD33 — No silent history truncation

Payload >64KiB, но внутри configured model/input budgets, обрабатывается в заявленном режиме, а не молча теряет старые факты. Oversized current input/prior также ограничен; data loss не маскируется под DCP.

### AUD34 — Output retention versus model preview

Нужный факт после первых 2048 bytes tool output остаётся доступен в разрешённом result/blob/read continuation. UI preview bounded, raw output не размножается в нескольких lifetime-long buffers.
