# T64 — publish the native oc2 on crates.io

Owner explicitly authorized crates.io publication on 2026-10-15, replacing the
0.0.1 bootstrap with the real application. Publish version 0.1.0; subsequent
corrections use new versions, not replacement of published archives.

## Contract

- `cargo install oc2 --locked` installs the native application as one `oc2`
  executable. Keep the existing core/adapters/TUI boundaries; publish their
  dependencies before the binary package. No launcher, Node/Bun, shared service,
  runtime grammar download, auto-update or installer service.
- Include all embedded prompts, skills, themes and 39 syntax grammars. Package
  archives must fit crates.io limits. If lossless recompression is required,
  preserve every uncompressed source/license byte and the existing syntax oracle.
- Original project source remains MIT. Ship existing third-party/source-derived
  notices and complete licenses inside affected packages; package metadata must
  not relabel the existing AGPL DCP components as MIT.
- Document installation, source-build prerequisites and current limitations.
  Target qualification remains GNU/Linux x86_64; no new Fedora/macOS/Windows,
  static-linking, full-product READY or full OpenCode parity claim.

## Verification and delivery

1. Check normalized package contents, licenses, internal registry versions,
   package sizes and builds from extracted archives rather than workspace paths.
   Run the existing syntax regression suite if archive encoding changes.
2. Commit reviewed packaging changes and record a checkpoint before irreversible
   publication. Publish only these project packages with the configured crates.io
   credential; never print the credential. Preserve factual partial publication
   status on failure; do not repeat an unknown upload after interruption.
3. Install `oc2` from crates.io into an isolated temporary root with `--locked`;
   verify version/help and a bounded offline actual-binary fixture where feasible.
   Record versions, checks, limitations and delivery separately; push this branch.

Paid provider checks, user-config conversion and unrelated runtime fixes are not
part of this task. Existing T61/T62/E2E06 and VIS38 caveats remain unchanged.
