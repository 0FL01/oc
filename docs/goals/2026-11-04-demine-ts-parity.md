Synthetic Python SQLite показал: `mode=ro` читает WAL version 22, но меняет SHM bytes; `immutable=1` видит stale main version 0; read-only exclusive/nolock не дают универсального чтения. Существующий Rust `public_read_only_connection` использует `readonly_shm=1` с дополнительными условиями, а native server вызывает мутирующий `endpoint::root` до `Db::open`. Эскалирована граница: рекомендуемый data/schema-only refusal до PRAGMA/migrate с разрешённым штатным owner-lock/SHM housekeeping либо строгий zero-filesystem-mutation с отдельным WAL/journal preflight и синхронизацией. Решение owner не получено; storage open/migrate пока не изменены, frozen 6.5 не ослаблен. Остальные разрешённые части W6 продолжаются.
- 2026-11-04, W6.5 plan-only Review-Sol: эскалация подтверждена чтением фактического storage/native owner. Собственный WAL/journal reader **не признан необходимым**: SQLite умеет heap WAL-index при существующем stale SHM; in-process writable-map reuse не отдельный blocker свежего native preflight до первого writable open. Native preflight обязан удерживать ownership fence до рабочего открытия. Даже data/schema-only отказ должен исключать checkpoint/recovery при закрытии writable connection; доступный `SQLITE_DBCONFIG_NO_CKPT_ON_CLOSE` сам по себе не обеспечивает literal zero-filesystem-mutation. Рекомендация — явно согласовать root/lock/SHM admission exceptions и отказ до schema/data writes, migrations и application recovery; после решения сначала использовать существующие SQLite механизмы. Это review boundary, **не PASS W6 implementation**.
- W6.5 smallest unlock, proposal only: owner должен также явно определить SQLite checkpoint/rollback recovery. Рекомендуемый KISS-вариант — гарантировать неизменность **логического committed schema/data**, отказ до migrations и application recovery, разрешив штатные root/lock/SHM и SQLite physical recovery/checkpoint для чтения committed версии. Если физические DB/WAL/SHM bytes тоже обязаны остаться неизменными, нужен более строгий admission preflight; простая проверка внутри migrate не может считаться выполнением frozen 6.5.
