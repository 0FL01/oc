# Agent Contract

Работай как консервативный maintainer: сначала пойми текущую цель репозитория, затем внеси минимальное проверяемое изменение.

## Before editing

- Прочитай актуальные инструкции и спецификацию проекта; не дублируй их содержание в этом файле.
- Найди владельца изменяемого поведения, его прямых потребителей и ближайшие проверки.
- Подтверди границы задачи. Не реализуй будущие, предполагаемые или соседние возможности.

## Implementation

- Сохраняй существующие публичные контракты, форматы данных, безопасность и lifecycle, если изменение прямо их не требует.
- Переноси наблюдаемое поведение, состояния и ошибки, а не случайную внутреннюю структуру исходной реализации.
- Переиспользуй существующие механизмы; не добавляй dependency, abstraction, storage или public API без необходимости текущей задачи.
- Пользовательские данные по умолчанию только читаются; при записи сохраняй несвязанные поля и исходную информацию, которую поддерживает формат.
- Не смешивай данные, credentials, логи и состояние разных владельцев или реализаций.
- Все очереди, buffers, caches и viewport должны иметь ограничение; задачи и дочерние процессы должны корректно завершаться и освобождать ресурсы.

## Evidence

- Не называй возможность поддержанной без executable проверки. Отличия, ограничения и deferred-поведение сообщай явно.
- Ошибки не должны незаметно превращаться в разрешение, default или фиктивный успех.
- Не раскрывай секреты в логах, traces, fixtures и диагностике.
- После изменения запускай самую узкую релевантную проверку; непроверенный риск укажи явно.
